# ToolSpline

ToolSpline — минимальный статический каталог open-source инструментов для разработчиков и вайбкодеров. Данные лежат отдельно в `tools.json`, а поиск, фильтрация, сортировка и пагинация выполняются в браузере.

## Brief

- Цель: быстро находить полезные CLI и developer tools по названию, описанию и сценариям применения.
- Аудитория: разработчики, технические авторы и вайбкодеры.
- Стек: Vanilla HTML5, CSS3, ES6+ JavaScript, Native JSON; серверная часть не нужна.
- Дерево:

  ```text
  .
  ├── index.html
  ├── styles.css
  ├── app.js
  ├── tools.json
  ├── update-metrics.js
  └── README.md
  ```

- Источник данных: независимый JSON-файл `tools.json`.
- Non-scope MVP: авторизация, база данных, серверный runtime, клиентские GitHub-токены, live-метрики traffic/views/clones, комментарии из Issues/Discussions, редактирование каталога через UI.

## Data model

Каждый элемент `tools.json` — объект со следующими полями:

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `slug` | string | да | Уникальный идентификатор |
| `name` | string | да | Название инструмента |
| `description` | string | да | Краткое описание |
| `url` | string | да | HTTP(S)-ссылка на GitHub repository |
| `useCases` | string[] | да | Сценарии использования |
| `stars`, `forks` | integer или `null` | да | Публичные proxy-метрики популярности |
| `metricsUpdatedAt` | ISO 8601 string или `null` | да | Время последнего обновления метрик |
| `status` | enum | да | `ok`, `stale`, `unknown`, `invalid_url`, `removed`, `private` |
| `downloads`, `views`, `comments` | integer или `null` | нет | Опциональные метрики, недоступные публично в общем случае |
| `tags` | string[] | нет | Теги |
| `language` | string | нет | Основной язык |
| `license` | string | нет | Лицензия |
| `notes` | string | нет | Примечание для редактора или пользователя |

Пример полной записи есть в `tools.json`. Клиент нормализует пропущенные значения: массивы становятся пустыми, отсутствующие метрики отображаются как `—`, неизвестный статус — как `unknown`. Дубликаты `slug` не объединяются: первая запись остаётся, последующие показываются в предупреждении и не выводятся.

Рендеринг использует DOM API и `textContent`; необработанные значения из JSON не попадают в `innerHTML`. Ссылки допускаются только с протоколом `http:` или `https:`, иначе запись получает `invalid_url` и остаётся некликабельной.

## Search and filtering

- Подстрочный поиск идёт по `name`, `description` и `useCases`.
- Перед поиском строка обрезается, последовательности пробелов схлопываются, затем применяется `toLocaleLowerCase()`. Кириллица и латиница обрабатываются одинаково.
- `minStars` и `minForks` независимы и соединяются с поиском AND-логикой. Запись без нужной метрики не проходит заданный минимум.
- По умолчанию используется `stars desc`. Также доступны `stars/forks asc/desc`, `name asc`, `metricsUpdatedAt desc`; пропущенные числовые значения всегда идут в конец.
- `PAGE_SIZE = 10`. Любое изменение поиска, числовых фильтров или сортировки возвращает страницу на 1.
- Состояние хранится в query-параметрах `q`, `minStars`, `minForks`, `sort`, `page` и обновляется через `history.replaceState()` без перезагрузки.

## Metrics update

Скрипт не запускается сайтом и не выполняет запросы сам по себе. Для явного обновления запустите:

```bash
node update-metrics.js
```

Для проверки ответа API без записи файла:

```bash
node update-metrics.js --dry-run
```

Скрипт использует только встроенный `https` Node.js и публичный endpoint `https://api.github.com/repos/{owner}/{repo}`. При успехе он обновляет `stars`, `forks`, `metricsUpdatedAt` и ставит `ok`. При HTTP 403 ставит `stale`, при 404 — `removed`, при сетевой ошибке, невалидном ответе или прочем HTTP-ответе — `unknown`; старые метрики при этом сохраняются. Невалидные GitHub URL помечаются `invalid_url` без запроса. Скрипт продолжает обработку остальных записей и не падает из-за отдельной ошибки API.

Публичный GitHub REST API не даёт общедоступные traffic/views/unique clones без прав администратора репозитория. Поэтому `downloads`, `views` и `comments` остаются опциональными `null`, а `stars` и `forks` используются как безопасные proxy-метрики.

## Local run

Из корня каталога:

```bash
python3 -m http.server 8000
```

Откройте <http://localhost:8000/>. `fetch()` не работает корректно при открытии `index.html` через `file://`, поэтому нужен локальный HTTP-сервер.

## Verification

1. Откройте сайт и убедитесь, что карточки загрузились, первая страница содержит не более 10 элементов, а навигация показывает вторую страницу.
2. Проверьте поиск по фрагментам на русском и английском, включая пробелы и разный регистр.
3. Проверьте `minStars`, `minForks`, каждую сортировку и комбинацию поиска с обоими фильтрами.
4. Измените фильтр и убедитесь, что URL содержит параметры, а страница сбрасывается на `page=1` или скрывает этот default-параметр.
5. Откройте страницу с query-параметрами заново и убедитесь, что состояние восстанавливается.
6. Проверьте клавиатуру: skip link, видимый focus, поля, кнопки пагинации и ссылку карточки доступны без мыши.
7. В DevTools замените `tools.json` на пустой массив, битый JSON, `useCases: null`, дубликат `slug`, `stars: null`, URL `javascript:...` и HTML-текст вроде `<img src=x onerror=alert(1)>`. Ожидаются empty state/предупреждение, `invalid_url`, тире вместо метрики и отсутствие выполнения HTML.
8. Выполните `node --check app.js` и `node --check update-metrics.js`.

## GitHub Pages

Файлы можно публиковать из ветки `main` в корне репозитория или из папки `/docs` в настройках GitHub Pages. Для корня текущего репозитория достаточно закоммитить эти файлы, выбрать нужную ветку и директорию в Settings → Pages. Серверный runtime и сборка не требуются.
